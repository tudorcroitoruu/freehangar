Nintendo save integration - 2026-11-11

SaveSystem retains its existing compressed/obfuscated player JSON and save keys.
SaveBridge delegates to PlayerPrefs in the Editor and on desktop. In Switch
players it stores these values in a versioned UTF-8 JSON container with Base64
values, using NXSave and the selected user's mounted save archive. No ES3 is used.
There is no automatic transfer of desktop saves to Nintendo user profiles.

Includes current save, backup, settings, completed-level activity and bicycle
camera preferences. Existing save entry points now use the bridge. The bridge
initializes automatically; no scene component needs to be assigned manually.
Normal native writes are throttled to 15 real-time seconds; a persistent pump
retries pending changes. Failed writes/commits retain pending data. Background
and exit callbacks capture live world state and request a forced flush.
Unreadable/unsupported containers block loading and writing rather than silently
replacing the original data. Native errors are logged or raised.

The active Application.aarch64.lp64.nmeta override requires a startup user and
allocates 64 MiB each for user save data and journal; legacy PlayerSettings match.
This allocation must still be checked against worst-case world save sizes.

Validation: Unity 6000.3.27f1 editor compilation succeeded. Switch player C#
compilation succeeded against the installed SDK (existing project warnings).
The standard test-runner request timed out. NintendoSaveValidation.RunFocusedTests
then directly invoked the NUnit assertions inside Unity: all 12 cases passed.
Reports: output/SaveSystem/Switch/tests.txt and compilation.txt.
This is not a full IL2CPP build or a hardware persistence test.
