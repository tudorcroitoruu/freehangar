Switch startup investigation - 2026-11-11

Reported symptom: loading background appears, but no progress bar or menu.
Boot waits for GlobalManager.savesLoaded before calling LoadingScene.LoadScene.
GlobalManager previously let save-load exceptions escape its async Awake, leaving
that flag false permanently. SaveBridge also initialized outside this error path
in a BeforeSceneLoad callback.

Confirmed native API misuse: NXSave mounted a user's save archive without first
ensuring it existed. The installed SDK's fs_SaveData.h explicitly requires the
archive to exist before MountSaveData. EnsureSaveData creates missing archives
and leaves existing archives intact. NXSave now checks Ensure before Mount.
The actual device exception has not been supplied, so the reported device stall
still needs a first-launch/relaunch check after rebuilding.

SaveBridge now initializes on first access, within startup save loading.
GlobalManager records startup failures and releases its loading flag. Boot shows
a save-load error with A/Enter retry instead of silently waiting forever.
Failed loads are not replaced with an empty save. Bootstrap's initial wait uses
real time so a stale gameplay time scale cannot prevent startup.

Validation currently blocked: HDRP was removed from Packages/manifest.json while
19 source files still reference its types. Existing camera/settings/sky code has
CS0246 errors, plus shader imports reference missing HDRP includes. User asked
whether to restore the dependency (rendering stays URP) or complete its removal.
StartupSaveTests adds coverage for a corrupt record: error reported, loading
state released, success flag false, and original record unchanged. Not yet run.
